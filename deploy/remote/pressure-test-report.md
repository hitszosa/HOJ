# HOJ 远程压力测试结果

日期：2026-10-04，Asia/Shanghai。目标：`10.249.12.21:3100`，部署目录 `/opt/hoj`。

## 结论

目前可以把 **300–500 人的课堂使用作为有实测依据的目标**。500 个活跃学生持续查询，同时集中提交 500 份 C++ 程序，3 分钟内的日常请求没有错误，程序全部 AC。修复配置瓶颈后，1000 个活跃客户端的 90 秒测试也全部成功，但不等同于整节课或任意题目规模的长期容量保证。

无间隔、持续发请求的极限模型在 1500 客户端时出现约 2.5% 连接错误，P95 超过 3 秒，已停止进一步加压。不要把“1500 个持续请求客户端”理解为“1500 名普通在线学生”。混合接口的吞吐量拐点约为 1100–1200 请求/秒，继续增加请求并发会增加等待与失败。

## 机器与方法

- 两颗 Xeon E5-2620 v3 @ 2.40GHz，共 12 核；64GB 内存。
- 系统盘约 558GiB，测试后剩余约 448GiB。另一块约 558GiB 磁盘未挂载，本次未使用。
- C++ 评测器配置为 6 个任务槽。
- 使用 1000 个独立临时学生账号和登录会话，课程名单确实包含 1000 名学生。
- 通过统一入口测试题面、题单、课程、个人信息，并少量查询教师全班成绩；日常模型每个客户端两次请求间等待 1 秒。
- 负载由服务器本机的临时容器产生，限制 2 CPU、1GiB 内存。混合测试使用两个各限 1 CPU 的负载容器。结果包含生成器开销，排除了 Mac/VPN 网络链路。
- 共记录约 88.9 万次 HTTP 请求，以及 1540 次真实 C++ 提交。测试题含 10 个测试点；较重程序另增加 CPU 循环。

方法与停止阈值详见 [load-test-methodology.md](load-test-methodology.md)，脚本在 [load-test/](load-test/)。

## 关键实测结果

P95 表示 95% 请求的响应时间不超过该值。请求模型、时长和配置不同，不能直接按人数相互比较。

| 场景 | 持续时间 | 请求数 / 结果 | 吞吐量 | P95 | 错误率 |
|---|---:|---|---:|---:|---:|
| 300 活跃客户端，初始配置 | 35 秒 | 10500 次 | 292 请求/秒 | 95ms | 0% |
| 500 活跃客户端，初始配置 | 35 秒 | 17368 次 | 482 请求/秒 | 86ms | 0% |
| 1000 活跃客户端，最终配置 | 90 秒 | 88189 次 | 969 请求/秒 | 41ms | 0% |
| 500 活跃客户端 + 集中提交 500 份程序 | 180 秒 | 88867 次日常请求 | 491 请求/秒 | 52ms | 0% |
| 持续真实登录，500 并发客户端 | 20 秒 | 21669 次 | 1058 登录/秒 | 233ms | 0% |
| 无间隔请求，500 并发，句柄修复后 | 25 秒 | 28909 次 | 1136 请求/秒 | 468ms | 0% |
| 无间隔请求，1500 并发，最终配置 | 25 秒，含尾部等待约 41 秒 | 31371 次 | 751 成功请求/秒 | 3144ms | 2.52% |

3 分钟混合测试在文件句柄调整后、PHP 队列调整前进行；最终配置的千人测试在全部调整及评测容器重建后进行。修复前的千人短测曾通过，但较长复测出现错误，因此没有使用短测结果代替最终验证。

## 真实 C++ 评测

| 集中提交 | 接收错误 | 最终结果 | 全部排空时间 |
|---|---:|---|---:|
| 100 份普通程序 | 0 | 100 AC | 18.7 秒 |
| 300 份普通程序 | 0 | 300 AC | 50.0 秒 |
| 500 份普通程序 | 0 | 500 AC | 83.4 秒 |
| 100 份带额外 CPU 循环的程序 | 0 | 100 AC | 24.8 秒 |
| 500 份程序，同时有 500 活跃客户端 | 0 | 500 AC | 89.6 秒 |
| 重建评测容器后的 20 份程序 | 0 | 20 AC | 6.1 秒 |

普通程序大批量处理约 6 份/秒，附加 CPU 循环约 4 份/秒。这个结果含编译、10 个测试点与排队轮询，不能推算所有课程题目的评测速度。更复杂代码、更多测试点或接近时限的程序会更慢。

成绩核查包含全部 1000 名学生：实际提交的前 500 人全部 100 分，其余 500 人为 0 分；重复 AC 不重复计分，名单没有漏行。

## 发现并修复的问题

1. **编程 API 文件句柄软上限 1024。** 高频采样实际捕获到恰好使用 1024 个句柄，同期出现身份校验与连接失败。两个 API 的 `nofile` 已显式设为 65536，并通过进程实际限制验证。
2. **PHP 身份校验队列容量不足。** Nginx 日志明确出现连接 PHP Unix socket 时的 `Resource temporarily unavailable`。工作进程上限设为 32、等待队列设为 4096。平滑重载仍保留旧监听队列 511，完整重建后实际监听队列才变为 4096；最终千人 90 秒测试无错误。

这些调整已写入 [compose.yml](compose.yml)、[php-fpm-hoj.conf](php-fpm-hoj.conf) 和 [Dockerfile.core](Dockerfile.core)，不是仅在运行容器中的临时改动。

极端无间隔负载仍存在连接重置与长尾等待，未把剩余问题宣称为已修复。入口 Node 进程在吞吐量平台期接近占满一个 CPU 核，其他服务也有开销；当前证据支持继续分析入口代理和连接行为，不能把剩余错误单独归因于某个组件。

## 资源与清理

整个记录中宿主 CPU 采样峰值约 73%，混合负载阶段可用内存最低约 58.9GiB；没有内存耗尽，也没有发现其他业务容器。机器仍有资源余量，现有软件和请求路径比内存更先达到瓶颈。

已备份并删除本次 1000 个学生、课程、题目、1540 份提交和学生 PHP 会话，保留正式 `admin`。判题队列为 0。清理后重新验证 admin 统一登录、角色、空课程列表和模板下载；7 个平台服务正常运行，临时负载容器和监控进程已结束。清理前、后各有私有备份。

原始阶段指标汇总见 [pressure-test-results.json](pressure-test-results.json)。本机完整证据位于 `.local/remote-deploy/load`，服务器位于 `/opt/hoj/load-test`。

## 边界

没有测校园网/VPN 带宽、整节课持续负载、大附件上传、更多课程规模、SSO、AI 或 PDF。建议实际教学先按 300–500 人安排，保留判题排队提示；1000 人属于本次短期测试通过规模，尚未证明长期课堂服务水平。

收尾验证时，服务器回环地址及 `10.249.12.21:3100` 的登录页均返回 200，但 Mac 直连该端口出现空响应或连接重置。SSH 仍正常。这一网络访问问题尚未定位，不能据此宣称校外/VPN 链路已经通过验证。
