## 实现与失败处理

`POST /api/management/courses/{offering_id}/delete` 仅超级管理员、受信任 Origin 可调用，并核对 `MGMT-{management_id}` 课程关联。管理服务先调用编程服务删除，再删除管理课程；编程班级已不存在时可重复调用，以处理跨服务重试。

发布、班级提交和删除使用同一班级 MySQL 命名锁，题目删除与自由练习提交共用题目命名锁。等待锁时释放数据库连接，避免并发请求耗尽连接池；请求取消时关闭持锁连接，防止会话锁遗留。

删除前保存作用域内的行快照与生成题目的隐藏测试压缩包。线上快照持久化到 `/opt/hoj/data/course-local/course-delete-backups/`；目录 0700，行快照 0600。本次历史清理前还保存了原生课程库和判题库的完整运维备份，位于 `/opt/hoj/backups/`，文件 0600。备份独立于在线业务数据，不出现在页面里。

判题库有 MyISAM 表，两个服务也没有分布式事务，不能保证全局原子回滚。备份失败时不开始删除；进入清理后发生失败，教学班保持关闭、请求返回错误，可检查快照并重试。不要直接恢复整个数据库覆盖其他用户的同期写入；需要恢复时只恢复目标课程作用域。

没有新增数据库迁移。部署仅更新 native API、management API、management web 三个镜像，React web 沿用已部署版本。
