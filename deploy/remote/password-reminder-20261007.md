# 首次登录密码提醒

目标：新账号首次通过统一登录页面登录时，显示一次修改初始密码的建议。教师和学生一致；选择稍后修改后不再重复提示，换浏览器也不重复。右上角「我的账号」始终可以修改密码。

实现：沿用 `grader.users.password_expired` 作为待提醒标记，不增加表或迁移。统一身份同步保留标记。`POST /management-api/auth/password_reminder` 在事务中对当前账号执行条件更新，以原子方式领取提醒；身份、可信来源和 CSRF 校验沿用管理接口。新建及名单导入账号的默认待提醒标记继续生效。管理员重新设置待提醒标记会再提醒一次。

统一登录成功后、跳转目标页面前领取提醒，避免题库等跳转路径漏掉提示。弹窗提供「去修改密码」「稍后再改」。删除布局内反复弹出的旧逻辑及跨账号共用的浏览器关闭标记；保留中英文提示。

顺带修复共享账号修改密码：管理服务验证密码强度，再由原生账号服务验证旧密码并更新登录密码，同时更新管理密码哈希、清除提醒及旧管理会话。导入账号的随机管理哈希不再阻碍正确的原生密码修改。修改成功后退出并要求使用新密码重新登录。原生密码适配器只修改会话所属账号，拒绝不可信来源、无身份请求及相同或不足 8 字符的新密码，并撤销该账号其他 PHP 会话。原生会话缓存仍沿用既有短期 TTL。

验证记录位于 `.local/password-reminder/` 及服务器 `/opt/hoj/qa-fixes/password-reminder-verification.json`。生产账号密码不作测试修改；测试使用临时账号，结束后核对实际删除与原有账号字段不变。

部署镜像标签：`password-reminder-20261007`，更新 core、api、management-api、management-web；源码和账号表备份在服务器 `/opt/hoj/backups/password-reminder-*`。镜像构建及 PHP 语法检查通过后再替换服务，启动健康检查失败时恢复原镜像。

最终验证通过：本地管理后端编译、Vue 构建、原生 HTTP 9 项测试及服务器 49 次接口检查。验证首次领取、重复领取、新会话、并发两会话只一方领取、未登录/缺 CSRF/不可信来源拒绝、不能代其他账号消除提醒；错误旧密码、弱新密码拒绝，导入占位哈希下正确改密，旧密码失效、新密码登录及其他原生会话撤销。PHP 会话目录从默认 root 所有的 1733 调整为 www-data 所有的 0700，仅 Web 进程与 root 可枚举会话，以实际撤销同账号其他会话。

页面验收：学生首次弹窗，稍后修改正常进首页，再次登录不弹；教师首次弹窗及去修改按钮进入账号密码表单。服务器直连 HTTP 在本轮被校园网重置，浏览器通过临时的本地 SSH 代理验证实际服务器版本；接口从服务器本机实测。测试代理与 SSH 转发已关闭。

临时账号已实际删除，两轮共使用 8 个临时账号，最终核对账号、映射、会话、权限及登录日志均无残留。原有 3 个账号的密码、角色、状态及提醒字段保持不变。7 个服务均正常运行，健康端点复查通过。发布前备份：`/opt/hoj/backups/password-reminder-20261007-001247`。页面截图：`.local/password-reminder/first-login-reminder.png`、`second-login-no-reminder.png`、`change-password-entry.png`。
