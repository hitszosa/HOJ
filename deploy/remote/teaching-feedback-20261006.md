# 作业总览与班级名单成绩

发布版本 `teaching-feedback-20261006`，更新 `api` 和 `management-web`。题库前端继续使用 `question-ranking-20261006`。不修改数据库结构、密码或校园网配置。

总览和课程卡片此前读取旧管理系统的作业数据，编程题单发布到原生作业表后没有被统计。本次改为根据管理课程与原生授课班级的关联，读取实际发布的编程作业，显示已发布数量、可提交数量和最近作业，链接直接进入原生作业详情。无截止时间也会显示。数据读取失败时显示错误和重试，不显示虚假的零作业。

`GET /api/management/assignment-overview` 按当前账号的班级权限返回摘要。只统计有效班级的已发布或已关闭作业；学生不可见尚未开放的作业。可提交条件与作业规则一致：已发布、已开放，且未到截止时间或允许补交。已关闭作业不计入可提交数量。每班最多返回三项最近作业。

班级学生名单新增作业选择，默认最新一次，直接显示该次作业的加权成绩、通过题数及未提交/待评测提示。`GET /api/offerings/{oid}/student-roster` 新增可选 `batch_id`，验证所属班级后只聚合当前页学生的成绩。搜索、20/50 人分页及权限保持原有规则。点击成绩进入个人详情并展开所选作业，返回时保留作业选择和搜索条件。每题 AC 计 100 分，其余完成结果计 0 分，作业总分按正权重计算；AC 不会被后续错误或待评测提交覆盖。

用户管理的“密码已失效”改为“密码修改提醒”，取值为“建议修改”或“无提醒”，说明这不是账号停用状态。认证逻辑未改变。

## 验证

- 本地后端 HTTP 测试 9 项通过，后端构建、Vue 类型检查与生产构建通过；本地只读数据库检查 7 项通过。
- 服务器使用一次性 2 个教师、23 个学生、2 个班级、5 次作业和 6 次真实 C++ 提交验证，主流程及补充流程共记录 137 次 API 检查。
- 分页成绩与成绩导出一致，30/70 权重下只通过第一题得到 30 分；后续 WA 不覆盖先前 AC。已验证搜索、第二页、空作业、多次作业、学生拒绝访问教师名单、跨班作业与代码隔离。
- 补充验证待评测、允许补交、关闭及未来开放边界。初次测试对默认允许补交的作业误预期为不可提交，核对 `allow_late=1` 后修正测试预期并补验；产品规则未改变。待评测场景仅临时调整一次性测试提交，完成后恢复。
