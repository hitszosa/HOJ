# 教学平台并发压测方法

压测目标为 10.249.12.21 的当前教学平台，统一 HTTP 入口 3100；不访问其他服务器。压测前先备份，使用唯一前缀的临时账号、班级和题目，结束后按记录的 ID 清理。

## 负载含义

- 在线负载：独立学生登录会话，请求题面、题单、课程、个人信息，并少量查询教师全班成绩。每个客户端两次请求之间等待 1 秒。这是活跃客户端模型，不是 1 秒内打开完整页面的浏览器模型。
- 饱和负载：同样的混合接口，不等待下一次请求，逐级增加同时发请求的客户端，以找出延迟和错误率拐点。超过 1000 客户端时复用已创建的 1000 个独立账号。
- 登录负载：持续使用有效账号发起真实密码登录；每次登录使用独立 Cookie。登录风暴比正常课堂的登录频率高。
- 判题负载：不同学生同时提交 C++，测提交接口响应及队列全部排空时间，检查真实最终判题结果。简单程序与附加 CPU 循环分别记录。测试题含 10 个测试点，不能据此承诺任意题目的吞吐量。

## 发起与观测

负载从服务器本机通过统一 3100 端口发起，保留真实远程 Host、Origin 及 Cookie。这样排除当前 Mac/VPN 链路的波动，结果表示服务器端容量；不代表校园网的带宽或网络稳定性。

负载程序运行于独立临时 Docker 容器，限制 2 个 CPU、1GiB 内存，不安装常驻服务。负载生成器与平台共享机器，因此所得数字包含生成器开销。记录生成器事件循环延迟，避免把生成器无法发满请求误报为服务器容量。

每一档记录请求数、成功吞吐量、错误率、响应时间 p50/p95/p99、分接口统计、状态码。每 5 秒观测宿主 CPU、内存、负载、各容器占用、数据库连接和判题队列。在线档持续 35 秒，饱和及登录档持续 20 秒；另用 180 秒混合负载检验 500 人日常请求与 500 份集中提交同时发生，并复核最后配置下 1000 人在线 65 秒。

在线负载错误率超过 1% 或 p95 超过 3 秒即停止继续增加在线人数。饱和负载错误率超过 2% 或 p95 超过 8 秒停止该轮；内存可用低于 8GiB 时停止负载容器。判题批次必须先排空才能启动下一批，最长观察 10 分钟。

“最高通过档”只是这些请求、数据规模、时长和判定门槛下的结果；除非实际越过故障拐点，不能称为机器的绝对最大并发。正式课堂建议容量需留有余量，并继续验证更长时间、更多课程和更复杂题目。

压测期间保存原始配置结果；文件句柄及 PHP 队列修复后分别复测，报告明确标识配置与持续时间，不将修复前短测的通过结果当成修复后长期保证。
