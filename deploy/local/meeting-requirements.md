# 会议要求与当前实施范围

整理日期：2026-10-03。依据用户提供的会议记录；硬件与校内网络条件尚未现场验证。

## 核心目标

教学管理与编程评测优先，继续兼容旧 OJ。实验报告通过独立 Grader 入口处理，本系统不增加 PDF 批注、文档转换功能。教学管理和判题服务独立运行，账号与课程通过明确接口关联。

### 使用规模与课程

| 课程 | 预估规模 | 语言范围 |
| --- | --- | --- |
| C 语言／计算思维与人工智能 | 约 1300 人 | C |
| 全校 DSA | 1000 人以上 | C/C++ |
| 留学生课程 | 约 800 人 | C++，学生流程需英文 |

人数不能直接相加作为唯一用户数，课程间可能重叠。以约 300 人同时使用作为主要验收场景，500 人作为峰值场景。在线人数、每秒提交数和同时判题数分别测量，不承诺现有设备未经压测即可承载。

当前已经具备 C/C++ 判题；Java 从一期范围排除。Python 保留扩展能力，不作为本期必需功能。界面和服务部署还需要按学校实际使用范围配置语言入口。

## 权限规则

| 行为 | 学生 | 助教 | 任课教师 | 超级管理员 |
| --- | --- | --- | --- | --- |
| 查看本人课程、作业、提交与公开成绩 | 是 | 是 | 是 | 是 |
| 查看已有课程配置 | 本人课程 | 所属课程 | 只读 | 是 |
| 新建、删除课程，修改课程名称／学期 | 否 | 否 | 否 | 是 |
| 修改课程教师名单、跨课程分配教师 | 否 | 否 | 否 | 是 |
| 管理学生与助教名单 | 否 | 否 | 本人任课课程 | 是 |
| 发布作业、查看提交、评分与导出 | 否 | 所属课程 | 本人任课课程 | 是 |
| 创建、停用账号，重置他人密码，修改角色 | 否 | 否 | 否 | 是 |
| 查询师生用于名单管理 | 否 | 按实际入口授权 | 是 | 是 |
| 从 HOJ 导入并替换课程成员关系 | 否 | 否 | 否 | 是 |

这里暂将“普通老师只读”理解为既有课程配置与教师名单只读；任课教师仍维护本课程学生、助教及教学活动。此解释已向用户询问，待确认。若要求整个课程都只读，应进一步关闭教师名单写入。

本次修正管理中心后端授权与前端入口，禁止教师修改其他课程、将自己加入其他课程，以及通过用户角色变更获得管理员权限。修改与删除课程、账号管理不依赖隐藏按钮来保护，API 同时校验权限。HOJ 课程同步收归超管，防止通过重新导入恢复被移除的教师关系。

原 HOJ 的开班、班级设置与代码浏览权限仍需按最终规则统一验收，不能将管理中心的修正直接等同于全平台权限改造完成。

## 班级、导入和成绩

- 教学班与行政班不强绑定。一个学生可以参与多个教学班，不能沿用旧 OJ“一人一个班”的限制。
- 用户面向唯一的班级名称操作；数据库保留内部 ID 维护关联。班级名称唯一性、重名提示和已有数据迁移需要一起完成，不能只隐藏 ID。
- 学生导入至少支持“学号、姓名”两列。学号保留文本格式与前导零；重复导入按学号匹配，不能默认覆盖密码和角色。名单预览应区分新增、已存在与错误行。
- 教师端必须支持班级管理、成绩导出及按需打开学生代码。代码列表分页，源码点击后加载；慢查询原因用执行计划和接口计时确认，不能假定是前端或数据库问题。
- **分值配置在实验上，不在题目上。** 100% AC 对应实验满分。部分 AC 是按通过题数比例给分，还是全通过才给分，仍需确认；截止时间、重交取最好结果与补交规则也需明确。当前通过题数统计不等同于已经完成实验计分。
- 复杂度分析需要明确形式：教师填写理论分析，或用多组输入规模比较时间／内存。单次运行时间不能直接推导渐进复杂度，不把自动复杂度判定列为已实现功能。

## 部署资源与端口

| 资源 | 会议信息 | 暂定用途／限制 |
| --- | --- | --- |
| 华为桌面云 CPU 集群 | 系统盘约 900G，数据盘约 3.4T；有端口限制 | 首选候选，先核实分配到的 CPU、内存、虚拟化能力、对外端口及内网连通 |
| 华为 RH2288 | 双 E5，每颗约 6 核，3 × 600G | 独立判题或备用候选；核实具体型号、内存、磁盘阵列与系统状态 |
| DELL0／DELL1 | 跳板 | 管理访问，是否能转发业务流量须确认 |
| 旧台式机 | 启动存在不明问题 | 先做启动和稳定性检查，再考虑备用或增加判题工作节点 |
| 两位教师闲置服务器 | 可能被抽查 | 按会议意见排除 |
| 现有旧 OJ 台式机 | 个人网络账号，重启困难 | 保留现状作为回退，不先重启或覆盖 |

一期入口尽量通过一个学校允许的 HTTPS 端口，经反向代理转发网页和 API。数据库、对象存储和判题控制接口放在内部网络。是否能开放 443、映射其它端口，或者通过跳板访问，必须现场确认。

部署逻辑：网页／教学管理 → 数据库与任务队列 → 独立判题节点；实验报告 → 独立 Grader。机器有限时服务可共用硬件，但保持独立进程、数据和配置。判题隔离所需能力必须在桌面云实际环境验证，不能仅凭“CPU 集群”名称决定放置。

磁盘总量不是容量瓶颈的充分证据。需要测量判题耗时、工作节点吞吐、数据库查询、网络链路和备份恢复；不以磁盘大小推断 500 人承载能力。没有采购新设备的预算，方案优先复用上述可用资源。

## 上线顺序

1. **机器现场确认**：资源、开机、账号权限、端口、内网、磁盘健康、可安装的软件和判题隔离。记录实际可用配置。
2. **上线前必须完成**：权限隔离、学号姓名导入、多班关系、实验计分及导出、代码浏览、留学生核心英文流程、外部 Grader 跳转、备份与可重复重启。
3. **压测与试用**：先小班试用，再验证 300 人主要场景与 500 人峰值。分别记录登录／页面响应、提交吞吐、排队时间、判题时间与错误率。暂不填写未经测试的性能承诺。
4. **国庆后接 SSO**：先开本地账号；以后以稳定的学校身份标识绑定现有账号，保留班级、提交和成绩。不能只凭姓名自动合并账号。学校身份提供方、协议与返回字段待对接。
5. **后续功能**：课堂临时出题与评分、象征性考勤；移动端优化低于核心教学流程。复杂度分析按明确需求另行验收。

会议中的“明天／中秋后三天／十月份”属于原会议相对时间，需要根据现场处理结果重新排期。当前本地验收通过不等于学校服务器上线完成。
